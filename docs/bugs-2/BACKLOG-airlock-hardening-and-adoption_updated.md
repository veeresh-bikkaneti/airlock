Derived from a full-clone review of `main` (119 commits) on 2026-08-14. Every item below was verified against the actual code, not the rendered README — several things I expected to find missing were already implemented, and those are recorded in ADR-008 rather than here.

Prefix `AIR-H` = hardening (rock solid), `AIR-A` = adoption (appealing). Effort is rough: **S** ≤ half a day, **M** ≤ two days, **L** ≥ three days.

### Review notes on the merged PRs

- **AIR-H2's original bug description was overstated.** "Previously-declined key silently ignored" is real, but only in *interactive* Claude Code sessions — non-interactive (`-p`) mode always uses `ANTHROPIC_API_KEY` when present and never runs the approval check. A `claude -p` smoke test therefore cannot verify this fix either way; only an interactive-session test can. ADR-009 is corrected with the precise, sourced behavior (code.claude.com/docs/en/authentication). The change is still right to keep — `ANTHROPIC_AUTH_TOKEN` is Anthropic's documented variable for gateway/proxy routing and outranks `ANTHROPIC_API_KEY` in precedence, so it can't be shadowed by a leftover key some other tool set. That's a better reason than the one originally given. **Verification status (2026-08-14):** confirmed the injection mechanism (`ai-claude-on` sets `ANTHROPIC_AUTH_TOKEN`, never `ANTHROPIC_API_KEY`) and confirmed a raw `/v1/messages` request using only that credential shape reaches Ollama and gets a real Anthropic-format response back. Confirmed separately that this harness genuinely cannot drive an interactive `claude` session (piped stdin to non-`-p` `claude` hangs rather than completing) — the approval-prompt path itself stays unverified end-to-end; only a human running an actual interactive session can close that last piece.
- **AIR-H1 needs its raw output pulled, not just the summary table** — done, 2026-08-14. Orphan repro (`ANTHROPIC_BASE_URL` pointed at a dead port) correctly classified as an ORPHANED POINTER, correctly attributed as foreign (not airlock-set), correct carrier chain, correct sign-out/reboot fix. `Test-Doctor.ps1` run directly from the repo: 3/3 passed, verbatim output captured, not summarized.
- **AIR-H3's requirement #4 was unrealistic as written**, and the coding agent was right to say so instead of faking it: Windows doesn't expose another process's environment variables to plain PowerShell/.NET without native memory-read APIs and elevated rights, and `ai-doctor` (AIR-H1) never does this either — it only reads the *current* process plus a name/ancestry walk via WMI. The task list should have said "identify likely-carrier processes by name and ancestry," matching AIR-H1's actual approach, not "enumerate their env vars." Worth confirming what was actually implemented as the "honest equivalent."
- **A real config-drift finding surfaced outside the task list**: `ai-start`/`ai-stop` on the dev machine shell out to the *installed* copy at `~/.ai-platform`, which had drifted from repo source — missing an `ai-claude-on` undo block that `Stop-AI.ps1` already has in the repo. This means patches merged to the repo (including AIR-H1 and AIR-H2 above) are **not automatically live** in a shell until whatever syncs `~/.ai-platform` from source has been run. **Resolved 2026-08-14, see AIR-H13/ADR-011**: measured 14 files differing/missing before a `setup.ps1` run, 0 after — the resync mechanism already existed, it just hadn't been re-run. `ai-doctor` now detects this itself going forward.

## Known-good — do not "fix"

Recorded because a future reviewer (human or agent) will otherwise flag these as gaps:

- **`ai-claude-on` injects into the current shell rather than spawning a wrapped child.** Deliberate; see ADR-008's non-decision section.
- **`ai-claude-on` refuses non-Ollama backends.** Correct — vLLM has no Messages API. See ADR-009.
- **`ai-code -Model` validation already exists** (validated against `ollama list`). An earlier session note claiming the flag was silently discarded is out of date.
- **The README already warns about the `settings.json` `env` block trap**, including the exact `Connection refused` wording. It is accurate and should not be softened.
- **The Python tests already run in CI.** `ci.yml` has a second `memory-service-tests` job on ubuntu that installs requirements and runs `pytest tests/ -v`. An earlier draft of this backlog claimed otherwise; that was a truncated read of the file.
- **`scripts/Test-*.ps1` is auto-discovered by CI.** Any new validator named to that pattern is wired in with no workflow change — this is how `Test-Scene.ps1` runs.
- **`provider-policy.json` (intent) and `active-provider.json` (live truth) are deliberately separate.** Documented in the README's data model section; do not merge them.
- **`Get-ProcessAncestry` (AIR-H1) has a known, bounded PID-reuse edge case** — disclosed by the coding agent, not a defect to fix now. Windows recycles PIDs quickly; in a rare race, a walked "parent" could actually be an unrelated process that reused that PID after the real parent exited. `MaxDepth=12` bounds the blast radius (no infinite loop, worst case is a wrong process name in the printed chain, not a crash). Low priority; revisit only if it produces a confirmed bad diagnosis in practice.
